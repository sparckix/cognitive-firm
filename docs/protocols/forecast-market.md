# Forecast Market Interface

**Module:** `cognitive_firm.orchestration.forecast_market`

The forecast-market interface lets cognitive-firm consume forecast-market state
without owning a tenant's market implementation.

The kernel defines the portable read-model shape. Tenant overlays own contract
creation, forecaster wakeups, aggregation policy, objective resolvers, scoring,
calibration weights, and domain-specific externality analysis.

## Lifecycle Vocabulary

A tenant forecast market may be implemented as files, a service, a database, or
a message stream. To interoperate with the kernel, it should project current
state into:

```text
contract -> forecasts -> aggregate -> outcome -> score -> decision-use row
```

Common lifecycle states:

- `forecast_requested`
- `forecast_fulfilled`
- `aggregate_ready`
- `resolved_unscored`
- `resolved_scored`
- `voided`
- `malformed`

## Read Model

The kernel consumes `ForecastMarketSummary`:

- number of contracts;
- contracts awaiting forecasts;
- aggregate debt;
- score debt;
- decision-use rows;
- score rows;
- high-confidence misses;
- per-contract lifecycle state;
- allocation recommendation;
- reflexive insights;
- maintenance items.

The adapter accepts richer tenant summaries and normalizes them into this
shape. For example, a tenant can expose a `global_health.json` generated by its
own forecast pool, and the kernel can read it through:

```bash
python -m cognitive_firm.orchestration.forecast_market \
  --summary-json path/to/global_health.json
```

## Allocation Recommendations

The portable action vocabulary is:

- `run_now`
- `split_contract`
- `ask_another_independent_agent`
- `defer`
- `kill_branch`
- `request_evidence`
- `request_human_work`

These are routing recommendations, not authority grants. Mandates, charters,
evidence gaps, human work sessions, gates, and damage signals still constrain
dispatch.

## Tenant Boundary

Tenants own:

- forecast contract schema details;
- how independent forecasters are selected;
- live versus sealed market mechanics;
- probability aggregation;
- domain-specific outcome resolution;
- scoring and calibration policy;
- externality fields;
- whether forecasts affect budgets.

The public kernel owns:

- the read-model interface;
- org-surface integration;
- route vocabulary;
- documentation of the boundary;
- tests for adapter normalization.

## Why This Is an Interface

Some tenants may have mature forecast tooling before adopting cognitive-firm.
Duplicating that tooling inside the kernel would create drift. The interface
lets the kernel consume market state while tenants continue to evolve their own
market implementation.
